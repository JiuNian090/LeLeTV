# 项目通用规则

> 全量加载 — 每次任务开始前读取，用于任务分类与技能分派。

---

## 项目定位

- LeLeTV 是**自用**的视频搜索与播放平台，纯前端 SPA + Cloudflare 无服务器后端
- 架构约束：不引入构建框架（无 Vite / React / Vue），不引入未经评估的第三方依赖
- 新增 `js/` 模块必须同步登记到 `scripts/build-bundles.mjs` 的打包清单
- 部署与安全约束见 `.agents/rules/deployment-rules.md` 与 `.agents/rules/security-rules.md`

---

## 任务前置分类铁律（强制执行）

收到改动请求后，写任何代码之前：

### 第一步：任务分类

| 类别 | 判定标准 | 触发条件 |
|------|---------|---------|
| 🎨 UI/设计 | 修改外观、布局、样式、新建界面 | 用户描述涉及视觉/布局 |
| 🔧 Bug 修复 | 排查报错、异常行为、逻辑错误 | 用户说"报错""bug""不工作" |
| 🏗️ 新功能/复杂改动 | 新增模块、跨文件改动、架构调整 | 用户说"实现""添加""新增" |
| 🧹 代码改进 | 重构、简化、去冗余、性能优化 | 用户说"优化""重构""清理" |
| ✏️ 简单改动 | ≤10 行、文案/配置/单文件样式微调 | 明显是微小改动 |

### 第二步：分派技能

> 只看**实际存在**的技能（清单见 `.agents/skills/`，索引见 `AGENTS.md`）。

| 类别 | 加载 | 说明 |
|------|------|------|
| 🎨 UI/设计 | `.agents/rules/skill-scheduling-rules.md` 的「设计技能选择指南」 | 按任务特征选具体设计技能 |
| 🔧 Bug 修复 | `superpowers-systematic-debugging` | 先诊断再修复 |
| 🏗️ 新功能/复杂改动 | `scheduling-project-skills` + `karpathy-guidelines` | 先编排再编码 |
| 🧹 代码改进 | `codegraph impact` → 逐处修改 → `codegraph callers` 回查 | 改前先分析影响面 |
| ✏️ 简单改动 | 直接执行 | 不调用技能 |

### 第三步：执行纪律

- 任务跨多个类别时，按最高优先级执行：UI/设计 > Bug 修复 > 新功能 > 代码改进 > 简单改动
- 技能调用后按技能返回的指导执行，不得以"跳过"或"太简单"为由绕过分类
- 技能执行完成即结束调用，不常驻上下文

## 知识沉淀规则

- 个人调试笔记、偏好 → 用 `remember` 工具存入 memory
- 团队/项目知识（架构决策、API 变更） → 更新 `.agents/rules/` 下对应规则文件，或 `README.md`
- 已经落成代码注释或文档的内容不重复记录
